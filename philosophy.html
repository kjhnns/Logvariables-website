A tool, not a startup.

Variables is built to last.

Not "built to scale." Not "built to exit." Built to keep working, quietly, for as long as you need it.

Here's what that means:

No venture capital.

Nobody is pressuring this product to grow 10x or pivot to enterprise. Growth is nice. Sustainability is required.

One maintainer.

Variables is built and run by one person. That's not a limitation — it's a feature. One person means no committee decisions, no bloat, no "let's add a social feed." The product stays simple because there's nobody arguing it should be complex.

Your data is yours.

Export everything via API, anytime. CSV if you want. If Variables disappeared tomorrow (it won't), your data comes with you.

The MCP server is open source.

MIT licensed. Fork it. Read the code. Verify it does what it claims. The backend is hosted (that's the service you're paying for), but the interface layer is fully open.

Low cost to run. No reason to stop.

The infrastructure cost of Variables is a rounding error. There's no scenario where "the servers are too expensive" kills this product. It'll keep running because it costs almost nothing to keep running.

No growth hacking.

No "invite 5 friends to unlock a feature." No dark patterns. No emails begging you to come back. If the product is useful, you'll use it. If it's not, that's fine too.

I built Variables because I wanted a place to log things about my life and ask questions later. Then I connected it to my AI agent, and it became the most useful integration I have.

I don't need this to be a unicorn. I need it to work on Tuesday.

— Johannes
